HOEOS FORENSIC INVESTIGATION — FINDING A CLASSIFICATION
HTTP 405 Method Not Allowed on /api/verify/* Routes on Vercel
================================================================
Investigation ID: HOEOS-VERCEL-FORENSIC-2026-09-25
Target Domain:    gradifi.vercel.app
Date:             2026-09-25

[1] ROOT CAUSE CLASSIFICATION

  ROOT CAUSE: MIDDLEWARE NOT DEPLOYED TO PRODUCTION

  The API routes `/api/verify/*` are registered exclusively as Vite dev-server
  middleware via Vite's `configureServer(server)` hook in `verifyServerPlugin.ts`.
  Vite dev-server middleware ONLY executes during local development (`vite dev`).

  When building for production via `vite build` (executed on Vercel via
  `npm run build`), Vite compiles static single-page application (SPA) client
  assets into the `dist/` directory. No serverless functions, backend entry points,
  or server middleware handlers are generated or deployed.

  `vercel.json` configures a global wildcard single-page application rewrite:
    { "source": "/(.*)", "destination": "/index.html" }

  When the browser sends an HTTP POST request to `/api/verify/core` (or any other
  `/api/verify/*` route) on production Vercel (`gradifi.vercel.app`):
  1. Vercel's edge router matches the path against `/(.*)` and rewrites the request
     to serve `/index.html`.
  2. `/index.html` is a static asset hosted on Vercel CDN.
  3. Standard HTTP specification and Vercel Edge CDN policy enforce that static
     file assets only accept GET and HEAD requests.
  4. Vercel CDN immediately rejects the POST request with:
     HTTP 405 Method Not Allowed.

[4] SECONDARY FINDING — LOCALHOST OLLAMA ENDPOINT CONFIGURATION LEAK

  - Finding: Browser console reports `localhost:11434/v1/models:1 Failed to load: 404` / connection refused.
  - Classification: Configuration leak (local development endpoint hard-coded in client code).
  - Evidence:
    - `src/services/verify/aiFederation.ts` (lines 24-29):
      `const endpoint = 'http://localhost:11434/v1/models';`
    - `src/services/verify/server/gemmaServerHandler.ts` (line 28):
      `const ollamaHost = process.env.OLLAMA_HOST || 'http://localhost:11434';`
  - Cause: Client-side browser code attempts to probe `http://localhost:11434` directly from the user's browser in production, failing when no local Ollama service is running.
