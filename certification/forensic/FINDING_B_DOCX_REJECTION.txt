[1] ROOT CAUSE CLASSIFICATION

  ROOT CAUSE: NAIVE PKZIP LOCAL-HEADER PARSER FAILS ON STREAMING DATA DESCRIPTORS

  The function `unzipPackageTextFile` (and `unzipPackageMediaFiles`) in
  `src/services/verify/ingestionAdapters/officeZipAdapter.ts` implements a custom,
  hand-written PKZIP header byte scanner.

  The parser assumes that every ZIP entry's compressed size (`compSize`) and
  uncompressed size (`uncompSize`) are non-zero numbers stored directly inside
  bytes 18-25 of the entry's Local File Header (`PK\x03\x04`).

  Per the PKZIP File Format Specification (ISO/IEC 19822 & PKWARE APPNOTE section 4.3.9),
  when bit 3 of the General Purpose Bit Flag is set (`flags & 0x0008`), the fields for
  `compSize`, `uncompSize`, and `crc32` in the Local File Header MUST BE SET TO ZERO (0).
  The true sizes are stored either in a Data Descriptor following the compressed payload
  or in the Central Directory at the end of the file.

  In the rejected DOCX file, ALL 21 entries were encoded with `flags = 0x808` (bit 3 set),
  meaning `compSize = 0` and `uncompSize = 0` in every Local File Header.

  When `officeZipAdapter.ts` parses this file:
  1. It reads `compSize = 0` and `uncompSize = 0` from bytes 18-25 of the Local File Header.
  2. It calculates `payloadSize = compSize > 0 ? compSize : uncompSize;` -> `payloadSize = 0`.
  3. It extracts 0 bytes (`compressedBytes = zipBytes.subarray(dataStart, dataStart + 0)`).
  4. It advances `pos = dataStart + 0`, placing `pos` directly at the beginning of the compressed
     Deflate binary data payload (e.g. byte 30 of `_rels/.rels`), NOT at a `PK\x03\x04` header.
  5. In subsequent loop iterations, `zipBytes[pos]` fails the `PK\x03\x04` check, triggering `pos++`.
  6. The scanner searches byte-by-byte through compressed binary data, encountering false-positive
     signature matches, corrupting the archive traversal state, and failing to locate or decompress
     `word/document.xml`.
  7. `unzipPackageTextFile` returns `null`.
  8. `extractDocxText` catches `xmlContent === null` at line 196 and emits line 208:
     `"The uploaded file is not a valid DOCX package."`
