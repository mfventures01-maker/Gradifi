OFFSET CONTRACT
0 <= startOffset <= endOffset <= canonicalText.length
Canonical UTF-16 character index coordinate system established in P3.
Every span specifies half-open range [startOffset, endOffset).
Verification rule: canonicalText.slice(startOffset, endOffset) === matchedText.

SPAN CONTRACT
interface MatchedEvidenceSpan {
  spanId: string;
  startOffset: number;
  endOffset: number;
  matchedText: string;
  sourceId: string;
  matchType: string;
  matchPercentage?: number;
  evidenceType: 'EXACT_MATCH' | 'LEXICAL_MATCH' | 'OTHER_DETERMINISTIC_MATCH';
  requiresHumanReview?: boolean;
}

RENDERING MODEL
Document text is converted into ordered, non-overlapping RenderedSegments:
interface RenderedSegment {
  text: string;
  startOffset: number;
  endOffset: number;
  isMatched: boolean;
  spans: MatchedEvidenceSpan[];
}
Segments are mapped into HTML <mark data-evidence-span="..."> elements with full XSS escaping via DOM text nodes/HTML escape tables.
Terminology Rule: Always labeled "Matched text" / "Similarity evidence" / "Visual Evidence Boundary". NEVER labeled "PLAGIARIZED", "GUILTY", or "PROVEN PLAGIARISM".

OVERLAP POLICY
Deterministic segment boundary splitting:
1. Extract all startOffset and endOffset points across valid spans.
2. Sort unique boundary points in strictly ascending numerical order.
3. Form non-overlapping adjacent character slices [p_i, p_{i+1}).
4. Associate each slice with all overlapping spans covering that range.
5. Invariant: Every canonical character appears in the rendered output exactly once.

DUPLICATE POLICY
Identical spans ([10,20] and [10,20]) are deduplicated deterministically by (startOffset, endOffset, sourceId, matchType). Duplicate nested HTML tags are never generated.

UNICODE
UTF-16 code units matching P3 offset model. Verified across Café (accented), 中文 (CJK), العربية (RTL), and 🚀 (surrogate pair emojis). Visual highlight bounds align with canonical indices.

LINE ENDINGS
Spans crossing LF (\n) and CRLF (\r\n) boundaries preserve original document line structures without corruption or silent strip/normalization.

XSS SAFETY
All canonical document text and matched strings undergo HTML entity escaping (< -> &lt;, > -> &gt;, & -> &amp;, " -> &quot;, ' -> &#39;) prior to visual markup generation. Executable script tags (<script>alert("XSS")</script>) and event handlers (<img onerror=...>) render safely as literal text.

INVALID SPAN HANDLING
Invalid spans (startOffset < 0, endOffset > canonicalText.length, startOffset > endOffset, NaN, Infinity, or mismatched text slice) are rejected immediately and classified with diagnostic reason INVALID_EVIDENCE_SPAN. They are excluded from visual highlight rendering without silent clamping or corrupted offset repair guessing.

CANONICAL TEXT ROUND-TRIP
Invariant: stripHighlightingMarkup(renderHighlightedHtml(canonicalText, spans)) === canonicalText.
Proven byte-for-byte identical across all valid, overlapping, unicode, multi-line, and single-character test cases.

DETERMINISM
50 consecutive render runs produced identical rendered HTML and segment structure.
Zero random UUIDs, zero timestamps (Date.now()), zero Math.random() in span resolution or rendering.
Deterministic sorting: startOffset ASC -> endOffset ASC -> spanId ASC.

SOURCE MAPPING
Every highlighted passage (<mark data-span-id="...">) retains sourceId metadata. Clicking/selecting a highlight passage reveals the underlying source evidence record without modifying the G3 policy verdict.

AI AUTHORITY BOUNDARY
AI outputs (Nemotron / Gemini / Gemma) are strictly NON_AUTHORITATIVE_INTERPRETATION. AI chatter cannot generate or modify authoritative highlight spans; highlights are derived strictly from deterministic evidence.

G3 BOUNDARY
P4 highlighting represents similarity evidence only. G3 remains sole authority for plagiarism classification, risk levels, and human academic review policy. P4 does not calculate or override G3 verdicts.
