contract. It does NOT modify any scoring, segmentation, or
persistence code. It does NOT modify the existing legacy
officeZipAdapter.ts DOCX function; that function is left in place
but bypassed by the dispatcher. Deleting it is deferred to G5-M04.

The migration introduces exactly:
  - one new production file (docxExtractor.ts)

  - one new dependency (fast-xml-parser)
  - one new test file (docxExtractor.test.ts)
  - one acceptance fixture corpus (tests/fixtures/docx/)

No other production file is modified.

1. MODULE AND PUBLIC API
--------------------------------------------------------------------

FILE
  src/services/verify/ingestionAdapters/docxExtractor.ts

EXPORTS

  export async function extractDocx(
    input: Uint8Array | ArrayBuffer,
    options?: ExtractDocxOptions
  ): Promise<DocxExtractionResult>;

  export interface ExtractDocxOptions {
    maxBytes?: number;             // default 50 * 1024 * 1024
    maxDecompressedBytes?: number; // default 100 * 1024 * 1024
    maxEntryBytes?: number;        // default 20 * 1024 * 1024
    maxEntryCount?: number;        // default 5000
  }

  export interface DocxExtractionResult {
    success: boolean;
    segments: TextSegment[];
    canonicalText: string;
    canonicalTextHash: string;
    zipEntryCount: number;
    decompressedBytes: number;
    warnings: ExtractionWarning[];
    error?: ExtractionFailure;
  }

  export interface TextSegment {
    story: 'main';
    partName: string;
    paragraphOrdinal: number;
    runOrdinal: number | null;
    xmlPath: string;
    kind: 'text' | 'tab' | 'lineBreak' | 'paragraphBreak';
    rawText: string;
    canonicalStart: number;
    canonicalEnd: number;
  }

  export interface ExtractionWarning {
    code: ExtractionWarningCode;
    message: string;
    part?: string;
  }

  export type ExtractionWarningCode =
    | 'TRACKED_INSERTION_PRESENT'
    | 'TRACKED_DELETION_PRESENT'
    | 'FOOTNOTE_REFERENCE_IGNORED'
    | 'ENDNOTE_REFERENCE_IGNORED'
    | 'DRAWING_IGNORED'
    | 'EMBEDDED_OBJECT_IGNORED'
    | 'UNSUPPORTED_ELEMENT_IGNORED';

  export interface ExtractionFailure {
    code: ExtractionFailureCode;
    message: string;
    detail?: Record<string, unknown>;
  }

  export type ExtractionFailureCode =
    | 'INVALID_DOCX'
    | 'CORRUPT_PACKAGE'
    | 'MISSING_MAIN_PART'
    | 'EMPTY_DOCUMENT'
    | 'SECURITY_REJECTED'
    | 'UNSUPPORTED_FEATURE'
    | 'OVERSIZED';

CANONICAL HASH
  canonicalTextHash is FNV-1a-64 (same algorithm as documentNormalizer
  computeHash) over the UTF-8 bytes of canonicalText. The extractor
  does NOT import computeHash from documentNormalizer to avoid a
  circular dependency; it implements the identical algorithm inline
  and the two are verified equal in a fixture.

--------------------------------------------------------------------
2. INPUT CONTRACT
--------------------------------------------------------------------

- input MUST be Uint8Array or ArrayBuffer. String input is rejected
  with INVALID_DOCX.
- input MUST begin with the four bytes 0x50 0x4B 0x03 0x04 (PK\x03\x04).
  Any other prefix yields INVALID_DOCX before any decompression.
- input.byteLength MUST be <= options.maxBytes (default 50 MB).
  Any larger input yields OVERSIZED.
- The extractor does NOT trust the file extension, the MIME type, or
  the caller-supplied filename. Only the bytes are authoritative.

--------------------------------------------------------------------
3. ZIP SECURITY CONTRACT
--------------------------------------------------------------------

3.1 Pre-decompression validation
   The extractor MUST read the ZIP central directory before
   decompressing any entry, and MUST reject the archive without
   decompressing if any of the following holds:

     raw byte length                 > maxBytes             -> OVERSIZED
     central directory entry count   > maxEntryCount        -> SECURITY_REJECTED
     any entry declared size         > maxEntryBytes        -> SECURITY_REJECTED
     sum of declared sizes           > maxDecompressedBytes -> SECURITY_REJECTED
     central directory is malformed                          -> CORRUPT_PACKAGE
     any entry name contains '..'                            -> SECURITY_REJECTED
     any entry name starts with '/' or '\'                   -> SECURITY_REJECTED
     any entry name matches /^[A-Za-z]:[\\\/]/               -> SECURITY_REJECTED
     any entry name contains a null byte                     -> SECURITY_REJECTED
     'word/document.xml' appears more than once              -> SECURITY_REJECTED

3.2 Decompression
   Only the specific entry 'word/document.xml' is decompressed. No
   other entry is materialized. Decompression is performed with
   fflate's streaming `unzip` API so that a single oversized entry
   cannot be emitted before its declared size is re-verified.

3.3 Post-decompression validation
   After decompression, the byte length of word/document.xml is
   re-checked against maxEntryBytes. Any exceedance yields
   SECURITY_REJECTED.

--------------------------------------------------------------------
4. XML SECURITY CONTRACT
--------------------------------------------------------------------

4.1 Parser
   fast-xml-parser v4, configured as:
     ignoreAttributes: false
     attributeNamePrefix: '@_'
     processEntities: false
     htmlEntities: false
     allowBooleanAttributes: false
     parseTagValue: false
     trimValues: false
     parseAttributeValue: false
     stopNodes: []

4.2 Pre-parse rejection
   Before invoking the parser, the extractor scans the raw text of
   word/document.xml for:
     - any occurrence of '<!DOCTYPE'   -> SECURITY_REJECTED
     - any occurrence of '<!ENTITY'    -> SECURITY_REJECTED
   The scan is case-insensitive and operates on the raw bytes so
   that encoding tricks (UTF-8 with BOM, UTF-16) cannot bypass it.
   Non-UTF-8 encodings yield SECURITY_REJECTED.

4.3 Entity handling
   Entity references ('&amp;', '&lt;', '&gt;', '&quot;', '&apos;')
   are NOT decoded. They appear as their literal source characters
   in segment.rawText. Decoding is a downstream concern.

4.4 Attribute handling
   Attributes are preserved on the parsed tree but are NOT included
   in canonical text. The one exception is xml:space, which is read
   to control whitespace in w:t.

--------------------------------------------------------------------
5. WORDPROCESSINGML SEMANTICS
--------------------------------------------------------------------

5.1 Story coverage
   Only the main story (word/document.xml) is extracted.
   Headers, footers, footnotes, endnotes are NOT extracted.
   References to them produce a warning (FOOTNOTE_REFERENCE_IGNORED,
   ENDNOTE_REFERENCE_IGNORED) but do not fail the extraction.

5.2 Element coverage
   Handled:   w:p, w:r, w:t, w:tab, w:br, w:tbl, w:tr, w:tc
   Warned:    w:ins, w:del, w:footnoteReference, w:endnoteReference,
              w:drawing, w:object
   Ignored:   all other w:* elements

5.3 Segment emission rules
   w:p     -> emit paragraphBreak segment after the paragraph's runs
   w:r     -> increments runOrdinal, recurse into children
   w:t     -> emit text segment with rawText = character data.
              Whitespace handling:
                if xml:space="preserve" -> keep as-is
                else                     -> trim leading and trailing whitespace
   w:tab   -> emit tab segment
   w:br    -> emit lineBreak segment
   w:tbl   -> recurse into w:tr -> w:tc -> w:p in document order
   w:ins   -> include contained text; emit TRACKED_INSERTION_PRESENT
   w:del   -> skip contained text; emit TRACKED_DELETION_PRESENT

5.4 Canonical text assembly
   Segments are concatenated in emission order:
     text            -> rawText
     tab             -> '\t'
     lineBreak       -> '\n'
     paragraphBreak  -> '\n\n'
   No further normalization. No NFC, no lowercasing, no whitespace
   collapsing. Normalization is documentNormalizer's responsibility.

--------------------------------------------------------------------
6. SOURCE-MAP SPANS
--------------------------------------------------------------------

Each TextSegment carries canonicalStart and canonicalEnd, which are
byte offsets into the UTF-8 encoding of canonicalText.

canonicalStart[i]   = sum of canonical-encoded byte lengths of
                      segments 0..i-1
canonicalEnd[i]     = canonicalStart[i] + canonical-encoded byte
                      length of segment i

Segment positions are contiguous: no gaps, no overlaps.

The spans are stable: identical input bytes yield identical spans.

The spans enable G4 highlighting: given a finding with a
canonicalStart..canonicalEnd range, the UI can identify the exact
character positions in the canonical text.

--------------------------------------------------------------------
7. TYPED FAILURE TAXONOMY
--------------------------------------------------------------------

Every failure returns success: false with error.code set to exactly
one of:

INVALID_DOCX          - not a ZIP archive, or archive lacks required
                        parts in a way that indicates the file is not
                        a DOCX
CORRUPT_PACKAGE       - ZIP central directory malformed, or a
                        declared entry cannot be read
MISSING_MAIN_PART     - word/document.xml not present in the archive
EMPTY_DOCUMENT        - word/document.xml parsed but produced zero
                        text segments after accounting for all rules
SECURITY_REJECTED     - a ZIP or XML safety limit was exceeded, or a
                        forbidden pattern was detected
UNSUPPORTED_FEATURE   - a required feature could not be processed
                        (e.g., encrypted archive). Most unsupported
                        features are warnings, not failures.
OVERSIZED             - raw input byte length exceeded maxBytes

Failures NEVER throw. The extractor's promise always resolves.

--------------------------------------------------------------------
10. DETERMINISM CONTRACT
--------------------------------------------------------------------

For identical input bytes:

  - segments array identical in order and content
  - canonicalText identical (byte-for-byte)
  - canonicalTextHash identical
  - zipEntryCount, decompressedBytes identical
  - warnings array identical in order and content

The extractor MUST NOT:
  - call Date.now()
  - call Math.random()
  - depend on locale
  - depend on Object.keys iteration order without sorting
  - call OCR or any external service
  - use any environment variable
