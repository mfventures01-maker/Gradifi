## 2. Root Cause Analysis

1. **Parser Rigidity**:
   In [geminiServerHandler.ts#L111](file:///c:/Projects/Gradifi/src/services/verify/server/geminiServerHandler.ts#L111), the code expects `process.env.GEMINI_SERVICE_ACCOUNT_JSON` to be directly valid for `JSON.parse()`. When provisioned in Vercel as a single-line or multiline secret, the environment variable can:
   - Be wrapped in surrounding quotation marks (`"..."`).
   - Have escaped newlines or escaped quotation marks (`\"`).
   - Be encoded as Base64.
2. **Missing Normalization**:
   The parser does not sanitize or normalize the raw environment string:
   - Trimming whitespace.
   - Stripping surrounding enclosing quotes.
   - Attempting Base64 decode if the string starts with `ey` or does not begin with `{`.
   - Handling escaped quotes `\"` or escaped newlines `\n`.
3. **Dual-Credential Strategy**:
   The repository and earlier tests (`tests/verifyCore.test.ts`) also reference `GEMINI_API_KEY`. If `GEMINI_API_KEY` is provisioned alongside or instead of `GEMINI_SERVICE_ACCOUNT_JSON`, the handler should support both robust service account parsing and API key fallback so that either authentication mode can be certified.
